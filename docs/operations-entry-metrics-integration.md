# 运营数据入口行为新增指标

2026-09-22：用户确认暂无新增接口文档或指标编码，本次先完成前端展示并标注“待接入”。

## 展示顺序与统计口径

四项指标在“入口行为”中紧接“收藏-接驳车次数”，顺序如下。未返回收藏指标时，追加到现有入口行为卡片末尾。

| 顺序 | 指标名称 | PV | UV |
| --- | --- | --- | --- |
| 1 | 入场引导使用次数 | 点击“我要入场”按钮的次数 | 该行为的去重人数 |
| 2 | 离场引导使用次数 | 点击“我要离场”按钮的次数 | 该行为的去重人数 |
| 3 | 地图导航使用次数 | 所有实际拉起地图导航的次数，不是导航按钮点击次数 | 该行为的去重人数 |
| 4 | VR 导航使用次数 | 所有实际拉起 VR 导航链接的次数，不是导航按钮点击次数 | 该行为的去重人数 |

PV、UV、环比和趋势均由后端统计。实际拉起的事件触发时机及 UV 去重标识需由 H5 与后端确认；不能将进入 VR 导航页面的事件直接等同于实际拉起 VR 链接。

## 当前前端行为

- 接口未返回对应指标时，展示“待接入”，PV/UV 显示“—”，不显示环比，不开放详情、趋势及导出。
- 占位卡片的 `pending:*` 仅用于本地渲染，不作为接口指标编码，也不会提交到后端。
- 若 `GET /api/v1/admin/stats/overview` 的 `entry` 已返回同名指标，使用真实接口卡片替换占位，保留其 `code`、名称、口径、数值及环比。名称匹配忽略空白和连接横线；正式编码确定后可改为按编码匹配。
- 现有业务指标和数据快照仍由接口提供，前端不生成或推算统计数值。

## 后续接入

后端需确认四项正式 `code`，在 overview 的 `entry` 中按现有 KPI 结构返回 `group: "entry"`、`name`、`hint`、`value`（PV）、`uv`、`prev`、`change`、`change_text`。真实零值应返回 `0`，不能以缺失卡片代替。

同一指标编码需同时支持现有趋势、明细和导出接口：

- `GET /api/v1/admin/stats/trend`
- `GET /api/v1/admin/stats/details`
- `GET /api/v1/admin/stats/details/export`

卡片接入后沿用现有时间和活动筛选，趋势、明细及导出统一携带后端返回的 `code` 与当前筛选参数。H5 埋点、后端聚合和正式接口联调不在本次前端占位展示中实现。
