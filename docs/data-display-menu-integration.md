# 数据展示菜单的过渡与后续接入

## 当前范围

后端暂时保持现有接口和菜单记录。侧栏将原“数据展示”页面展示为：

```text
运营管理
└─ 数据展示（前端展示目录）
   ├─ 运营数据（原页面）
   └─ 安保数据（可点击的示例展示页）
```

前端展示目录只在已通过权限过滤的导航数据上派生，不写入 `AuthSession`、菜单接口返回数据或角色权限树。用户没有原运营页面授权时，不会通过这个适配器新增导航入口。

“安保数据”注册为 `/operations/security-data`，路由名为 `security-data`，通过侧栏可进入展示页面。目前暂时沿用运营数据页面 `/` 的访问授权，不新增角色权限选项，不向后端提交虚拟目录或安保导航项的 ID。

临时授权映射集中在 `src/config/data-display.ts` 的 `SECURITY_DATA_AUTHORIZATION_PATH`，由 `src/config/navigation.ts` 注册项的 `authorizationPath` 使用。`canAccessPath` 必须找到真实、启用且祖先链完整的运营页面；仅有 `dashboard:view` 权限码或只获授权“数据大屏”不足以访问安保页。超级管理员也需要有效的运营菜单和祖先链。`visible` 仍只控制导航展示，隐藏运营菜单不会撤销其原有地址访问权限。

侧栏、默认跳转和页面访问使用同一套授权判断。即使后端提前返回安保菜单，临时映射仍优先要求运营页面授权；已有安保入口不会被适配器重复添加。真实多级目录不再套一层前端目录。

## 当前展示数据与时间窗口

安保页的数值、活动和选择占比统一读取 `src/modules/security-data/data.ts` 的固定示例数据，不调用尚未接入的安保接口。后续替换数据源时，应保留展示层的指标定义及统计分母含义，并用后端响应更新数据模型。

页面按原截图呈现，不额外增加示例标记或页头、当前/历史状态标记、返回当前按钮、统计页脚及补充说明。固定数据及接入状态记录在本文档中。场景分布采用三列布局：上排依次为入场接驳车、检票口、分区三张卡；下排为离场接驳车一张卡，以及横跨两列的离场分区卡。红、橙、绿颜色仅复现原型样式，不代表已确认的真实风险等级或阈值。

时间窗口逻辑位于 `src/modules/security-data/use-security-data.ts`，统一按北京时间 `Asia/Shanghai` 处理。时段为凌晨 `[00:00, 08:00)`、上午 `[08:00, 12:00)`、下午 `[12:00, 18:00)`、晚间 `[18:00, 次日 00:00)`。页面初始化及刷新选中今天的当前时段，未来日期和今天的未来时段不可选；从历史日期切回今天时，若原时段尚未开始则切换到当前时段。历史窗口隐藏“当前在线”指标。

活动提示按所选日期与活动日期的交集展示。页面保留截图原有“每 5 分钟实时刷新”的静态文案，但当前尚无业务数据轮询或实时刷新能力，控制器仅更新本地时钟；正式接入接口时再实现对应的数据刷新逻辑，不能将当前状态描述为已接入实时数据。

修改时间窗口用于展示筛选状态，当前固定指标不会据此伪造重新计算的统计结果；正式接入后，开始时间和结束时间应作为真实查询参数传给安保接口。

## 现有权限的保留

以目前提供的菜单接口数据为例：

| 菜单 ID | parent_id | 前端显示名称 | 既有路径或权限 |
| --- | --- | --- | --- |
| 1 | 0 | 运营管理 | 目录 |
| 10 | 1 | 运营数据 | `/`、`dashboard:view` |
| 11 | 10 | 导出 | `dashboard:export` |
| 13 | 1 | 数据大屏 | `/operations/data-screen`、`dashboard:view` |

这些 ID、父子关系、权限码和已有角色关联保持原样。角色权限树只对原页面的显示名称做兼容映射：页面类型为 `2`、路径为 `/`，且原名称为“数据展示”或“数据看板”时显示“运营数据”。适配不依赖固定 ID，也不根据 `dashboard:view` 批量改名，因此同权限码的“数据大屏”仍保持原名称。

角色创建和权限全量替换继续提交真实接口菜单 ID，例如 `menu_ids: [1, 10, 11]`。当前前端校验仍要求至少勾选一个 `menu_type=3` 功能点；本次不改变这项既有规则。未来开放仅查看运营或安保的角色时，需要同步确认后端接受页面查看授权，并调整前端校验、提示和统计。

## 后续后端接入

不需要为了这次调整新增字段。后端可以通过现有数据迁移或初始化机制增加菜单记录，继续使用现有菜单查询和角色授权接口。

1. 增加真实“数据展示”目录记录，类型为 `menu_type=1`，父节点为运营管理，目录本身不代表业务查看权限。
2. 保留原页面 ID `10` 及 `dashboard:view`，将其命名为“运营数据”、迁入新目录；保留导出 ID `11` 及其父节点 `10`。
3. 增加真实“安保数据”页面记录，类型为 `menu_type=2`，使用独立权限码。当前前端路径为 `/operations/security-data`；最终路径和权限码以与后端确认的契约为准，正式授权不再复用运营数据的查看权限。
4. 补齐已有角色对新目录的祖先关联，保留原有运营与导出授权；普通旧角色不自动获得安保页面权限。目录授权不能隐含授予所有子页面。
5. `/api/v1/admin/menus` 返回完整的新目录及菜单记录；`/api/v1/admin/auth/me` 的 `menus` 返回获授权菜单和完整祖先节点。授权变更后更新服务端权限缓存，并刷新前端当前用户会话。
6. 安保业务接口执行对应的后端权限检查，前端菜单过滤不能替代接口鉴权。

前端导航已经支持递归目录。后端返回真实嵌套目录后，该结构直接用于导航，不再匹配旧版顶层页面的临时分组逻辑。正式接入需删除 `SECURITY_DATA_AUTHORIZATION_PATH` 及安保注册项的 `authorizationPath`，将注册表和路由元数据切到后端约定的独立权限码，并移除不再需要的旧接口展示适配，接入安保业务数据。**仅返回新菜单不会自动解除临时授权映射**，这些改动应在同一次联调中完成。角色权限树继续使用接口返回的真实目录、页面及功能点，不手动补造记录。

仓库中的历史后台菜单 JSON 不作为已完成后端迁移的证据，本次不修改它来模拟菜单落库。

## 联调验收

- 旧接口下，运营页面与导出行为保持原样；具备真实运营页面权限时可打开安保示例页，仅有数据大屏权限时不可打开。
- 运营页面或其祖先缺失、停用、出现循环时，普通用户及超级管理员均不能通过临时映射访问安保页；隐藏菜单仅隐藏入口。
- 角色新增、权限回显、复制和全量替换保留原有真实 ID；不会提交任何 `presentation:` ID。
- 临时映射保留期间，即使接口提前返回安保菜单，仍验证导航与地址访问都要求运营页面权限。
- 删除临时授权映射并启用独立权限后，分别验证仅运营、仅安保、两者都有、两者都无的导航和路由访问结果。
- 只读角色允许保存时，验证前后端校验已同时支持页面权限，且目录单独勾选不被当作业务授权。
- 验证旧角色迁移后的祖先目录完整、数据大屏权限不受影响、权限撤销后菜单和地址访问同步失效。
